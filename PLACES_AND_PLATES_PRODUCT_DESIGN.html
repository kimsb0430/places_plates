여행지와 식당 사진을 부담 없이 기록하고, 서버에는 업로드 원본을 남기지 않으면서 지도 정보와 개인의 기억을 편안하게 읽는 여행 아카이브 설계안입니다. 첫 버전은 개인 페이지로 시작하고 향후 사용자별 페이지가 있는 커뮤니티로 확장합니다.

3분 사진 10장을 올려 초안 기록을 만드는 목표 시간
01 / PRODUCT

제품 정의

Places & Plates는 사진 갤러리와 여행 블로그의 중간이 아니라, 장소·방문·사진을 연결한 개인 기록 시스템이다. v1은 소유자 한 명의 페이지로 시작하되 모든 기록에 소유자를 명시해 향후 회원마다 독립된 페이지를 가질 수 있게 한다.

📥

빠른 수집

사진을 먼저 올리면 촬영일과 위치를 바탕으로 방문 초안을 자동으로 묶는다.

✍️

가벼운 보완

필수 입력은 최소화하고, 평점·메뉴·비용 같은 정보는 필요할 때 단계적으로 연다.

📖

편안한 열람

사진과 개인 기록을 먼저 보여주고 주소·지도·영업 정보는 보조 계층에 배치한다.

핵심 제품 결정: “완벽하게 작성해야 저장할 수 있는 폼”을 만들지 않는다. 업로드 즉시 비공개 초안으로 저장하고, 나중에 30초 단위로 기록을 보완할 수 있게 한다.
02 / OUTCOMES

목표, 비목표, 사용자 이야기

첫 버전의 성공은 기능 개수가 아니라 “미뤄 두지 않고 기록할 수 있는가”와 “몇 달 뒤 다시 읽고 싶은가”로 판단한다.

목표

  • 사진 10장의 초안을 3분 안에 만든다.
  • 모바일에서 시작한 기록을 PC에서 그대로 이어 쓴다.
  • 공개 이미지의 메타데이터 검출과 처리 완료 후 임시 원본 잔존을 0건으로 유지한다.
  • 여행·장소·방문을 분리해 재방문 기록이 자연스럽게 쌓인다.
  • 사진과 개인 기록을 지도 정보보다 먼저 읽게 한다.

v1 비목표

  • 복사·화면 캡처의 완전 차단 — 웹 기술상 보장할 수 없다.
  • 다른 사람 페이지의 공동 편집 — 향후에도 각 계정은 자신의 기록만 편집한다.
  • 여행 일정 예약·결제 — 기록 경험과 별도 제품 영역이다.
  • 소셜 피드·팔로우 — v1에서는 개인 아카이브 완성도를 먼저 검증한다.
  • 외부 장소 정보의 실시간 동기화 — 비용과 변경 위험을 줄인다.
Story 1

빠른 시작

기록자인 나는 사진부터 올리고 싶다. 그래야 제목과 세부 정보를 정하지 못했어도 기억을 잃기 전에 보관할 수 있다.

Story 2

쉬운 보완

기록자인 나는 자동 제안된 날짜와 장소를 확인하고 일부만 고치고 싶다. 그래야 반복 입력 없이 정확도를 높일 수 있다.

Story 3

편안한 회상

나와 초대받은 방문자는 여행 흐름 안에서 사진과 감상을 읽고 싶다. 그래야 정보 목록이 아니라 실제 경험처럼 기억할 수 있다.

Story 4

안전한 공개

기록자인 나는 원본과 촬영정보를 노출하지 않고 사진을 공개하고 싶다. 그래야 개인정보 유출과 무단 활용 위험을 낮출 수 있다.

Story 5

분류와 분포

방문자인 나는 맛집과 여행지를 나눠 보고 지도에서 기록 수를 확인하고 싶다. 그래야 관심 있는 기록과 지역을 빠르게 탐색할 수 있다.

Story 6

나만의 페이지

향후 가입한 회원인 나는 다른 사람의 기록을 편집하지 않고 내 사진과 장소만 관리하고 싶다. 그래야 독립적인 여행 페이지를 만들고 서로 구경하거나 공유할 수 있다.

03 / PRINCIPLES

설계 원칙

입력 편의와 결과물 가독성이 서로 충돌하지 않도록, 원본 데이터는 구조화하되 작성 화면에서는 필요한 순간에만 항목을 드러낸다.

① Upload first

제목을 정하기 전에 사진부터 올릴 수 있다.

② Smart defaults

날짜·위치·사진 순서는 자동 추정하고 사용자가 확인한다.

③ Progressive fields

제목, 장소, 한줄평 외 항목은 접어 둔다.

④ Story first

결과 화면은 지도 데이터보다 사진과 개인 경험을 먼저 읽게 한다.

07 / CATEGORY & MAP EXPLORATION

맛집·여행지 카테고리와 지도 탐색

모든 공개 게시물은 맛집 또는 여행지 중 하나의 대표 카테고리를 갖는다. 사용자는 카테고리를 선택하고, 개별 게시물을 차례로 읽는 리스트와 전체 분포를 보는 지도 사이를 자유롭게 전환한다.

🍽️

맛집

식당·카페·바·디저트 가게 기록. 공통 게시물 정보에 평점, 추천 메뉴, 가격대, 대기시간, 재방문 의사를 선택적으로 추가한다.

🧭

여행지

명소·자연·문화시설·쇼핑·체험 기록. 추천 방문 시간, 소요 시간, 볼거리, 여행 팁, 계절 정보를 선택적으로 추가한다.

분류 규칙: 대표 카테고리는 정확히 하나만 선택한다. 카페·디저트·사찰·전망대처럼 더 자세한 분류는 복수 태그로 추가해 카테고리 구조가 복잡해지는 것을 막는다.

카테고리 합계

상단의 전체 42, 맛집 18, 여행지 24는 현재 공개 범위와 검색 조건에 맞는 전체 게시물 수다.

지도 영역 합계

지도를 이동하거나 확대하면 현재 화면 경계 안의 게시물 수가 다시 계산된다.

묶음 마커

가까운 게시물을 묶고 숫자를 표시한다. 확대할수록 장소별 또는 게시물별 마커로 분리한다.

동일 장소 기록

같은 장소를 여러 번 게시했다면 마커 카드에서 방문 기록 수와 각 게시물을 함께 보여준다.

리스트·지도 연동 규칙

사용자 행동리스트 반응지도 반응
맛집 탭 선택맛집 게시물만 표시하고 선택한 정렬을 유지한다.맛집 마커와 묶음 수만 표시하며 영역 합계를 갱신한다.
게시물 카드 선택선택 상태를 표시하고 상세 열기 동작을 제공한다.해당 마커로 이동하고 대표 사진·제목·방문일을 표시한다.
마커 또는 묶음 선택해당 장소의 게시물을 목록 상단으로 이동하거나 좁혀 보여준다.묶음이면 확대하고, 단일 장소면 정보 카드를 연다.
지도 이동·확대“현재 지도 영역만 보기”가 켜진 경우 목록도 같은 범위로 갱신한다.화면 경계 기준 게시물 수와 묶음을 다시 계산한다.
리스트·지도 전환카테고리, 검색어, 정렬, 지도 위치와 선택 게시물 상태를 유지한다.

PC

리스트 탭은 기존의 큰 카드 중심 구성을 유지한다. 지도 탭을 선택하면 지도 약 70%, 축소 게시물 목록 약 30%로 전환하고, 목록의 게시물에 마우스를 올리면 해당 마커를 강조한다.

모바일

지도 탭에서는 지도를 먼저 크게 표시하고 현재 영역의 게시물을 하단 가로형 축소 카드로 넘겨본다. 전환해도 필터와 지도 위치가 유지되며 게시물 상세는 전체 화면으로 연다.

09 / IMAGE PROTECTION

이미지 개인정보·저작권 보호

브라우저에 표시된 사진의 복사나 화면 캡처를 완전히 금지할 수는 없다. 서버가 업로드 원본을 임시로 처리한 뒤 삭제하고, 메타데이터를 제거한 정제 이미지와 워터마크가 합성된 공개본만 보관해 개인정보 노출과 무단 이용의 가치를 낮춘다.

보호 원칙: 업로드는 휴대폰·PC에 있는 원본 파일을 변경하거나 삭제하지 않는다. 서버는 수신한 원본을 임시 영역에서만 사용하고, 정제 마스터와 공개본 생성·검사가 끝나면 임시 원본을 자동 삭제한다.

서버 워터마크

CSS 오버레이가 아니라 이미지 픽셀에 Places & Plates를 합성한다. 워터마크 정책 버전을 기록해 정제 마스터에서 다시 생성할 수 있게 한다.

공개 범위별 워터마크 정책

공개 범위제공 이미지워터마크접근 정책
비공개고화질 정제 마스터없음 또는 작은 표시로그인한 소유자만 접근, 업로드 원본 다운로드는 제공하지 않음
링크 공유웹용 축소본하단 모서리 20–30% 투명도추측 불가능한 공유 토큰, 필요 시 만료 처리
전체 공개웹용 축소본픽셀에 합성된 모서리 워터마크원본 접근 차단, 외부 사이트 무단 삽입 방지
강화 보호낮은 해상도 파생본중앙의 옅은 반복 워터마크중요 사진에 선택 적용, 감상성 저하를 사전 안내

워터마크 기본값

  • 표준 문구: Places & Plates
  • 사진 너비의 12–18%, 가장자리에서 3% 안쪽
  • 배경 밝기에 맞춰 흰색 또는 검은색 자동 선택
  • 사진별 적용 위치와 워터마크 버전을 저장

보조 억제 기능

  • 우클릭 메뉴와 이미지 드래그 억제
  • 이미지 외부 직접 삽입 방지 정책
  • 다운로드 버튼은 공개 화면에 제공하지 않음
  • 페이지와 파일 정보에 저작권자 표시
명시적 한계: 우클릭 차단과 워터마크는 복사를 불가능하게 만드는 보안 장치가 아니다. 개발자 도구, 네트워크 요청, 화면 캡처, 자르기와 AI 제거가 가능하므로 “완전한 다운로드 방지”는 v1의 목표가 아니다.

보안 완료 조건

상황Given / When / Then 완료 조건
정상 게시원본에 GPS와 카메라 정보가 있을 때 전체 공개하면, 공개 파생본에서는 EXIF·XMP·IPTC가 검출되지 않고 서버 합성 워터마크가 보인다.
원본 미보관정제 마스터와 공개본 검사가 성공하면 임시 업로드 원본이 삭제되고, 비로그인 방문자는 물론 운영자도 서버에서 원본을 다시 다운로드할 수 없다.
처리 실패메타데이터 제거 또는 워터마크 생성이 실패하면, 해당 사진은 공개되지 않고 운영자에게 재처리 상태를 표시한다.
재처리공개 정책이나 워터마크가 변경되면 메타데이터가 제거된 비공개 정제 마스터에서 새 공개본을 생성하며 업로드 원본에 의존하지 않는다.
로컬 원본업로드 완료 후에도 사용자의 휴대폰·PC에 있던 사진 파일은 어떤 방식으로도 수정되거나 삭제되지 않는다.

12 / DELIVERY

권장 구현 방향

사진 처리와 위치 정보는 비용과 개인정보에 직접 영향을 주므로 임시 업로드 원본, 정제 마스터, 공개 이미지를 분리하고 모든 기록에 소유자 경계를 둔다.

frontend

독립된 Next.js + TypeScript 프로젝트. 페이지는 app, 기능은 domain, 공통 요소는 shared로 나눠 Spring Boot와 비슷하게 책임을 드러낸다.

backend

독립된 Java + Spring Boot + Gradle REST API. 도메인별 controller·service·repository·entity·dto 구조와 Spring Security 소유자 권한을 적용한다.

이미지 파이프라인

임시 원본에서 메타데이터가 제거된 정제 마스터와 공개 파생본을 만든 뒤 검사가 끝나면 임시 원본을 삭제한다.

Google 지도 연결

Google Maps JavaScript API와 Places API (New)를 사용한다. 지도 탭을 열 때만 동적 지도를 로드하고, 장소 선택 후 Place ID·좌표를 저장해 공개 페이지에서 같은 장소 정보를 반복 조회하지 않는다.

탐색 인덱스

게시 상태·카테고리·좌표를 함께 조회하고 지도 경계 및 묶음 단위 집계를 빠르게 계산한다.

저장소 구조: 하나의 Git 저장소 아래 frontend/와 backend/를 두는 모노레포로 운영한다. 프론트엔드는 Supabase 데이터베이스·Data API·저장소에 직접 접근하지 않고 /api/v1 Spring Boot API만 호출한다. 운영 PostgreSQL은 Supabase를 사용하며 관리자 마이그레이션 역할과 RLS가 강제되는 애플리케이션 역할을 분리한다. 상세 규칙은 PROJECT_STRUCTURE.md와 docs/SUPABASE_DATABASE.md를 기준으로 한다.
실패 시 안전하게 닫기: 메타데이터 제거, 워터마크 생성 또는 게시 전 검사 중 하나라도 실패하면 임시 원본을 공개하지 않는다. 사진은 비공개 처리 상태에 머물고, 재시도 만료 후 임시 원본을 자동 삭제하며 필요하면 사용자가 다시 업로드한다.
13 / PHASES

제작 순서

화려한 홈 화면보다 업로드→초안→상세 기록의 핵심 루프를 먼저 완성한 뒤 탐색 기능을 확장한다.

Phase 1

안전한 기록·탐색 루프

인증, 사진 보호 파이프라인, 초안, 맛집·여행지, 리스트, 지도·묶음 수, 장소 연결, 상세 페이지

Phase 2

고급 탐색 경험

여행 타임라인, 연도·태그·평점 필터, 사진 모아보기, 일괄 편집, 지도 성능 최적화

Phase 3

회원·커뮤니티 확장

일반 회원가입, 사용자별 고유 페이지, 공개 프로필 탐색과 링크 공유. 각 회원은 본인 기록만 편집하며 타인의 페이지는 열람한다.
