# 2026-08-26 Daily Report

## 한국어

- 목표: Cloud Run에서 ICC 색상 프로필이 있는 JPEG 정제 시 발생한 LCMS2 네이티브 라이브러리 오류를 제거한다.
- 완료: Google Buildpack 설정을 Java 21 다단계 Dockerfile로 교체하고 실행 이미지에 `liblcms2-2`를 설치했다. 애플리케이션은 UID 10001 비루트 사용자로 실행하며 CI가 실제 이미지를 빌드해 `liblcms2.so.2`와 실행 사용자를 검사하도록 추가했다. 병합 후 기존 Cloud Build 트리거가 Dockerfile을 무시하고 인라인 Buildpacks를 실행하는 문제를 확인해, 저장소의 `backend/cloudbuild.yaml`이 Docker 이미지 빌드·푸시·Cloud Run 서비스 갱신을 담당하도록 후속 보완했다.
- 중요 파일: `backend/Dockerfile`, `backend/.dockerignore`, `backend/cloudbuild.yaml`, `.github/workflows/verify.yml`, `scripts/verify-cloud-run-container.ps1`, `PROJECT_STRUCTURE.md`, `docs/DEPLOYMENT_CHECKLIST.md`
- 검증: 병합 전후 비밀 검사, 컨테이너 계약 검사, 프론트 lint·타입 검사·Vercel 및 Sites 빌드와 공개 산출물 검사, 백엔드 전체 테스트·배포 JAR 생성이 통과했다. GitHub CI의 실제 Docker 빌드와 `liblcms2.so.2`·비루트 UID 검사도 통과했다. 병합 커밋 `9bace43`의 Cloud Build는 인라인 Buildpacks가 Java 21을 찾지 못해 실패했고 이전 리비전 `places-plates-api-00027-gvg`가 트래픽 100%를 유지했다.
- 결정: Cloud Run 백엔드는 암묵적인 Buildpack 시스템 패키지에 의존하지 않고 저장소의 Dockerfile을 실행 이미지 기준으로 사용한다. Cloud Build 트리거는 인라인 구성이 아니라 버전 관리되는 `backend/cloudbuild.yaml`을 사용한다.
- 위험: Cloud Build 트리거를 `backend/cloudbuild.yaml`로 전환하고 새 리비전을 배포하기 전까지 ICC 색상 프로필을 읽는 JPEG 정제 요청은 같은 오류로 실패할 수 있다. 기존 실패 초안과 임시 업로드는 운영 만료 정책 범위에서만 유지된다.
- 다음 작업: 수정 PR 병합과 Cloud Run 재배포 후 기존 실패 항목을 재시도하고 정제·파생본 생성·READY 전환을 운영에서 확인한다.

## 日本語

- 目標: Cloud RunでICC color profileを含むJPEGをsanitizeするときに発生するLCMS2 native library errorを解消する。
- 完了: Google Buildpack設定をJava 21のmulti-stage Dockerfileへ置き換え、runtime imageへ`liblcms2-2`を導入した。ApplicationはUID 10001の非root userで実行し、CIが実imageをbuildして`liblcms2.so.2`と実行userを検査するようにした。Merge後、既存Cloud Build triggerがDockerfileを無視してinline Buildpacksを実行する問題を確認し、repositoryの`backend/cloudbuild.yaml`がDocker imageのbuild・push・Cloud Run service更新を担当するように補完した。
- 重要ファイル: `backend/Dockerfile`、`backend/.dockerignore`、`backend/cloudbuild.yaml`、`.github/workflows/verify.yml`、`scripts/verify-cloud-run-container.ps1`、`PROJECT_STRUCTURE.md`、`docs/DEPLOYMENT_CHECKLIST.md`
- 検証: Merge前後のsecret検査、container contract検査、frontend lint・型検査・VercelおよびSites buildと公開成果物検査、backend全test・配備JAR生成が成功した。GitHub CIの実Docker buildと`liblcms2.so.2`・非root UID検査も成功した。Merge commit `9bace43`のCloud Buildはinline BuildpacksがJava 21を見つけられず失敗し、旧revision `places-plates-api-00027-gvg`がtraffic 100%を維持した。
- 決定: Cloud Run backendは暗黙的なBuildpack system packageへ依存せず、repositoryのDockerfileをruntime image基準として使用する。Cloud Build triggerはinline設定ではなくversion管理された`backend/cloudbuild.yaml`を使用する。
